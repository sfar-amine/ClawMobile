## Clock probe qualification (Claude, 2026-10-09, on Amine's request)

Measured on the S24: the per-event `python3` probe cost 133.6 ms p50 and 156 ms max, synchronously, in the Companion process that relays Voice audio. This would block the relay and skew t25p/t30p. The probe is now run once per telemetry session, asynchronously, reading MONOTONIC, BOOTTIME and MONOTONIC back to back. Then `boot_ns = process.hrtime.bigint() + (BOOTTIME − midpoint MONOTONIC)`.

- Each calibration re-qualifies `process.hrtime` as CLOCK_MONOTONIC: the probe readings must fall inside the hrtime bracket. Otherwise the clock is disabled; no substitution is made.
- S24 measurements: offset stable to ±2 µs; derived stamp 0.32 µs.
- Events emitted before the offset is known are stamped at emit time and written once it is known (queue bounded to 256). `flush()` awaits pending writes.
- A new session recalibrates. A change of more than 1 ms between sessions is reported (`status().driftUs`, `suspendDetected`) and never smoothed.
- An injected `clock` keeps the former synchronous fixture path.
- Validation: `test-voice-m1-telemetry.cjs` 11/11 (adds calibrated mode, recalibration/drift, bracket failure, real calibration). The other M1 and Companion CI scripts are unchanged and pass.
- Close-time check, aligned with the A10 analyzer (`6c10e41`): when the Voice owner socket closes, a second asynchronous probe writes `t99` (turn 0) for that sid, with `x.clock_drift_us` = offset at close − offset used during the session. A suspend inside the session (|drift| ≥ 1000 µs) therefore excludes the whole sid in `voice-m1-analyze.py`. `t99` is a C1 clock-check event, not a latency stage. Tests 12/12.
