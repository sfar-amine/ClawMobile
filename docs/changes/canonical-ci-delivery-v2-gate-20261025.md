# Canonical CI validates the shared delivery contract — 25 October 2026

Core and Android CI could previously succeed even when their changed delivery records used a noncanonical version2 shape. The observed records had object-shaped scopes/tests and an unsupported merge eligibility value. A successful compilation did not validate those records.

The existing `tools/localci.py` now calls the existing playbooks contract before any job worktree or Android build. Its only schema owner is the complete immutable `sfar-amine/samantha-ui-playbooks` checkout698322f70d454151b802e3c5850db82f4a38d046. Git fetch provenance and the fetched commit are checked. An isolated Python subprocess imports the original `validate_range` and `validate_note` APIs from that tree; `require_v2=True` is explicit because the Core base has no playbooks delivery-policy file. Only notes changed in the PR range are assessed; unrelated historical notes are not reinterpreted.

The complete pin is required: the original contract imports `agent_runner`, which imports committed policy and native-selection helpers and hashes its own pinned source files. Those imports use the standard library and pinned repository files; this check does not instantiate a model, read credentials, publish, deploy, or modify runtime state. No schema is copied into Core. `-I -B` excludes the candidate checkout and ambient PYTHONPATH from import selection and avoids writing bytecode into the pin. The temporary owner checkout is removed on success or failure.

Core and Android retain their existing workflow/build owners and every original step. Successful logs name the schema owner, exact pin, strict-v2 result and assessed note paths. A refusal fails before compilation and preserves the caller's checkout/artifacts. No new registry, route, store, scheduler, retry, capability or MCP contract is introduced.

Regression evidence: all56 tests in `tools/test_localci.py` passed, including real pinned-schema Core/App admission, version1 refused without a base policy, mislabeled object-shaped v2 refused, missing change record refused before execution, inherited historical note ignored, candidate PYTHONPATH unable to substitute a validator, and the existing APK receipt/lifetime checks. The suite fetches the real pin once for these schema integration tests; its synthetic workflows and APK fixtures do not claim production or device qualification. The first focused run correctly refused an unchanged fixture Markdown page; the fixture was updated, with no assertion weakened. Failed evidence is retained privately.

The tests remain in the existing mandatory canonical CI contract step (`python3 ../tools/test_localci.py`). Final full canonical CI on the composed GitHub head remains required. Rollback is a normal revert of this scoped commit followed by qualification of the resulting owner; no S24 action is needed for this CI-only change. All six MCP primitives are unchanged.
