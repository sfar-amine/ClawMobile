# Chantier 1 C4 — Host opt-in runtime semantic dialogue port

The existing `FastPathPorts` can load the pinned playbook `intent_dialogue` owner in-process when the host sets exactly `SAMANTHA_INTENT_INTERPRETER=1`. There is one backend per request, with no global admission cache. Typed interpretation and confirmation objects remain in-process. Natural answers use the coordinator hook, and a missing backend or refused DATA policy never invokes the lexical resolver. Legacy callers without the host opt-in keep their existing path. Live voice/delegation and private QA ingress retain their own owners.

The additive MCP transport exports `INTENT_INPUT_PROTOCOL=mcp-input.v1`, accepts `RunnerOptions.intentContext`, and sends the bounded context on the existing helper private pipe. The helper requires the new explicit flag, the host opt-in, a UID-owned FIFO, the MCP surface and the dialogue entry. Original text stays exact; every external narrative is client-reported regardless of fields claimed inside it. A regular file, mismatched message, wrong surface, oversized envelope or helper without protocol support refuses. Raw context is not put in arguments or environment. Authenticated app/WhatsApp event provenance is supplied by the host port; MCP never becomes server-verified.

Dependencies: playbooks C2/C3/C7 and B's `intent_dialogue.make_intent_dialogue_port`/Graph/interpreter must be present in the pinned runtime before opt-in. This commit does not activate the flag, transmit data, install a provider or qualify the DATA profile. Unknown provider evidence remains blocked before generation. Read execution is in-process under the canonical Graph. Durable effects remain explicitly unqualified until the existing Continuum/RemoteBridge owner can revalidate private persisted grants; no alternate effect executor is introduced. Migrated MCP execution additionally requires its canonical RemoteBridge receipt owner, so a successful preview alone is not an executable MCP receipt.

Targeted fixture verification: TypeScript build; **11/11** new Python port/pipe tests; **11/11** existing Web tests; **10/10** Node private transport assertions; existing capability-first plugin tests pass. Fixtures use mock ports and temporary helpers, no model, network, S24 or business effect. Canonical exact-head local CI and integrated qualified provider tests are separate checks. Rollback: remove host opt-in and revert this additive port. No new store, router, scheduler, daemon or business capability.
