# MCP — require a server-bound service before interpretation

A generic client conversation context could previously enter the Pulse-only interpreter. Existing MCP tools now require a separate closed service selector and a service admitted in their authenticated server client record. C12 binds the selection through its existing WeakMap and private v2 packet; missing, forged or expired selection fails before helper/private owner work. Calls without a new context retain their historical path.

The paired playbooks change authenticates every read-capability field with a process-private MAC and passes the whole canonical service catalogue internally. A selector grants neither professional DATA nor provider or business permission. No client configuration, S24 source or runtime is changed.

Targeted checks before publication: TypeScript compile; Node 120/120 across the new scope suite and five inherited owner/input suites; Python helper 18/18; Worker tool/provenance, routing 6/6, Google OIDC 8/8 and local OAuth RPC 8/8. Invalid server configurations also refuse.
