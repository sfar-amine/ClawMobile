# R10 — origine canonique d'une demande REQ

Une demande libre créée pendant un tour Companion porte l'identifiant public du fil à sa création. Le Companion ajoute la première ligne fixe `[companion-session:<sessionId>]` au message destiné à l'agent OpenClaw, en utilisant le même identifiant déjà normalisé et conservé par le registre des runs. Le corps utilisateur, le routage, les attachements, le runId et la clé Gateway restent distincts ; une ligne ressemblante dans le corps n'est pas une origine officielle. La normalisation existante n'est pas modifiée.

Le skill existant `clawmobile-capabilities` passe cette origine à `context-event.sh <surface> open_thread --session <sessionId> <texte>`. Seul ce marqueur transport du tour Companion fournit l'origine : aucun rapprochement par texte, date, curseur, runId ou clé Gateway, aucune recherche dans l'environnement. Les autres callers conservent la commande sans option. L'option est fermée aux open_thread ; format exact `[A-Za-z0-9_-]{1,80}`, doublons et options invalides refusés avant création des dossiers de l'ingress.

Memory Core reste propriétaire : migration additive `events.session_id TEXT NULL`, événement JSON version 2 avec champ optionnel `sessionId`. Les anciennes lignes et événements version 1 restent lisibles et non liés. L'identité legacy hash(surface/kind/supersedes/texte) reste identique lorsqu'aucune origine n'est fournie ; une origine explicite ajoute un suffixe discriminant au hash. Deux demandes identiques de fils distincts n'ont donc pas le même événement. Rejouer l'événement retrouve sa révision ; même id avec session différente donne `event_session_conflict`, sans écraser ni ajouter d'événement.

Le resolver playbooks restitue l'origine de l'ouverture canonique exacte dans `GET /v1/control/requests/{REQ-n}?contract=2`. Les mises à jour, closes et annulations liées par supersedes conservent l'origine du root ; les chaînes ambiguës/cycliques ne donnent pas de lien. Un root legacy NULL n'est jamais réattribué à partir d'une mise à jour. Un événement nouveau avec origine explicitement différente d'une origine non NULL dans sa chaîne supersedes est refusé par l'ingestion (lecture bornée à 64 ancêtres). Les closes sans option restent compatibles. Les règles de thèmes historiques ne servent pas à attribuer une session. Les demandes de fils distincts restent isolées.

La façade Companion conserve le champ public validé de la projection canonique et refuse une valeur hors format, sans convertir une clé Gateway ni deviner un fil par défaut. Les demandes Situation sans producteur de conversation restent `sessionId: null`. Aucun nouveau store, scheduler ou journal ; paiement inchangé. Les lectures ne créent pas de session.

Validation locale : six tests du véritable helper Bash et SQLite (migration, ids/revisions legacy, deux origines, rejeu, conflits, options invalides sans effets, supersedes) ; fixture CLI Gateway contre le registre réel et le préfixe officiel, marker utilisateur conservé comme corps ; validation des liens de la façade ; build, CI existante et régressions Memory Core via copie Termux à shebang portable. Les nouveaux tests sont exécutés séparément pendant l'édition CI réservée à un autre lot. Aucune preuve de recette S24 n'est déclarée.
