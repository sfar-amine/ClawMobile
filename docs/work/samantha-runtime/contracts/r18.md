Le défaut n’est pas reconstruit depuis config : le Gateway tient compte du modèle, du runtime et de sa politique.

Aucun calcul de jetons ni estimation ; aucune jauge ajoutée aux lignes de la liste.

Une seule lecture CLI `sessions.list {search:"companion-",limit:100}` partagée avec la liste. Cache volatil TTL2s et single-flight ; froid≤6s (budget propriétaire5,5s), chaud≤1,5s. Sans catalogue observé, liste vide/issue et choix modèle désactivé ; dernier catalogue connu affichable mais changement désactivé si source stale ou TTL60s expiré. Aucun nouveau store, scheduler ni daemon.

Une transition terminale enregistrée par le propriétaire des runs invalide la vue de sa session ; le prochain GET déclenche une relecture lazy partagée. Si une lecture capturée avant cette transition était déjà en vol, sa fin ne qualifie pas la jauge : contexte null, issue conversation_owner_refresh_pending et sélecteurs désactivés ; le GET suivant obtient une relecture post-invalidation. Aucune deuxième CLI dans le même GET. Échec de lecture : dernières métadonnées conservées et issue stale.
