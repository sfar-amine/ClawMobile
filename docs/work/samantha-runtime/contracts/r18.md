## Lecture

GET `/v1/conversations/{sessionId}/metadata` conserve les métadonnées R11 et ajoute `thinkingLevel`, `thinkingLevelSource` (`session`, `default` ou null), `thinkingLevels[]`, `hasActiveRun`, `thinkingChangeAvailable` et `context`.

Options : `thinkingOptions` de la ligne sessions.list, sinon `thinkingLevels[].id`. Pas de liste de niveaux locale ni de carte par modèle ; max et ultra sont conservés quand le propriétaire les propose. Override supporté → source session ; sinon thinkingDefault supporté → source default. Sans options : liste vide et thinkingLevel/source null, même si thinkingDefault existe. Le défaut n’est pas recalculé depuis config ou models.list.

`context` vaut `{usedTokens,windowTokens,percent,source:"gateway",measuredAt}` à partir de totalTokens/contextTokens/snapshotAt de la même ligne ; totalTokensFresh:true et nombres entiers sûrs sont obligatoires. Sinon null. Percent arrondi et borné0..100. Aucun jeton estimé, aucune lecture par ligne supplémentaire.

Une seule CLI sessions.list partagée avec la liste, cache volatil TTL2s et single-flight ; froid≤6s (budget propriétaire5,5s), chaud≤1,5s. Le catalogue provient uniquement du peek propriétaire R6/R21 ; GET ne lance aucun config/models/auth. Dernier catalogue stale affichable mais sélecteur désactivé.

La transition terminale d’un run invalide sa vue. Une ancienne lecture encore en vol laisse la jauge null, une issue refresh_pending et les sélecteurs désactivés ; le prochain GET relit une seule fois. Un échec garde les dernières métadonnées avec issue stale. Une vue pleine de100 lignes, hasMore:true ou totalCount supérieur au nombre lu ne prouve pas une absence : retour503, sans recherche par ligne ; absence dans une vue complète→404.
