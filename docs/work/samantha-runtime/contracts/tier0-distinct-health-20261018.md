# Tier0 soak — distinct health evidence and readiness before promotion

The S24 chronology supplied by Claude is preserved in `fixtures/foundations/s24-tier0-soak-20261018.json`. Promotion preceded the Gateway listening event. The original `health/current.json` was overwritten, so its exact producer PID and sample times remain unknown. The source reproduction is separate: one unchanged `generated_at` written once triggered rollback after two watchdog ticks. It demonstrates a defect in counting, not a recovered historical payload.

The watchdog now counts distinct post-grace producer timestamps, never polling ticks. A healthy new sample resets the bad sequence; two distinct bad samples still request the existing rollback. Pre-grace and out-of-order samples do not condemn a release. Missing/invalid timestamps cannot qualify one. If the declared soak deadline expires without usable refreshed evidence, it fails with `soak_health_evidence_unavailable`, preserving a bounded failure path rather than waiting forever. Emergency stop still blocks rollback effects. Each promotion clears evidence from the previous release.

`runtime-sync.sh` now waits for Gateway readiness before every Tier0 promotion, including when the plugin bytes were already current. It does not restart a healthy unchanged plugin. The probe matches the health producer's success/nonempty-body rule, with a 3-second timeout and a bounded body; HTTP200 with an empty body does not qualify. Existing retry count and readiness-before-promotion ordering remain bounded.

The existing Tier0 state retains the last consumed sample's timestamp, source, producer module, decision and at most32 critical capability states. A rollback appends the same content-free projection to the existing watchdog log through `bounded-log.py` (256KiB plus two archives); the installer copies this existing writer into Tier0 bin. No probe body, user text, account, token or free-form reason is logged. The original failed sample remains available after the rollback owner reads state.

Tests replay repeated and distinct samples, recovery between failures, pre-grace/out-of-order evidence, missing timestamps through deadline, emergency stop, bounded log rotation and five simulated soak windows. Runtime-sync tests cover unchanged-plugin promotion while Gateway is restarting or permanently unavailable, and empty HTTP200. These are off-device tests, **not five real deployments**. Claude owns the S24 deployment/receipt and the generalisation to other automatic managers is reviewed under the later F4.3 point.

No new store, daemon, registry, router, retry owner or HTTP route. The existing state, watchdog, health producer, readiness endpoint and rollback owner remain authoritative. No payment/monitorMs:1, live voice or bridge environment sanitation is changed.
