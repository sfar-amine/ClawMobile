## Source et projection

Audit S24 de Claude (programme31 §C8) : `~/.openclaw/agents/*/agent/openclaw-agent.sqlite`, table `session_nodes`, `entry_json` contient totalTokens/contextTokens/compactionCount. Le schéma public **exact OpenClaw2026.9.6** (`openclaw-state-read.worker.js`, OPENCLAW_AGENT_SCHEMA_SQL) confirme `session_key` comme clé canonique et `entry_json` comme enregistrement logique ; les colonnes promues ne sont pas une seconde source. La capture réelle PR82 (`a9f08e5`) confirme maintenant les 30 colonnes STRICT et 15 projections métadonnées sur trois agents, sans messages ni champs privés.

Le lecteur Python sélectionne uniquement le store `agents/main/agent/openclaw-agent.sqlite`, sans fenêtre temporelle, puis ouvre cette base avec URI `mode=ro`, `PRAGMA query_only=ON`, busy timeout250ms. SQLITE_LIMIT_LENGTH borne les valeurs natives avant leur matérialisation et un CASE SQL vérifie la taille byte avant de retourner entry_json ; un Python sans setlimit refuse plutôt que de lire sans borne. Il ne lit que `session_key,entry_json`, sans session_windows, messages, JSON sessions legacy, Gateway ou `openclaw sessions`. Il conserve les champs historiques de health.json : version1, checkedAtMs, sessions {key,sessionId,updatedAt,totalTokens,contextTokens,ratio,kind,status} ; compactionCount est une information additive, nullable. Les identities proviennent exclusivement du propriétaire, jamais de déductions par texte/time.

Tri déterministe updatedAt décroissant puis key. `kind` vaut cron si la clé contient `:cron:`, direct sinon. Une fenêtre absente, non finie ou non fiable selon la règle installée vaut 200000 ; une fenêtre fiable (`modelSelectionLocked`, ou source `runtime` / `resolved-v1` avec fournisseur, modèle et harness) reste inchangée. Un total illisible vaut0, et une fenêtre explicite0 laisse le ratio null. Tout contenu inconnu de l’entrée est éliminé ; aucun transcript, jeton, profil ou dump SQL n’est écrit ou journalisé. Les diagnostics d’échec sont fixes, sans chemins privés ni contenu de ligne.
