POST `/v1/control/memory/{eventId}/forget` {operationId} : owner natif, événement non financier de type decision/constraint ou learning importé. Le propriétaire context-store.py ingère un checkpoint MEMORY_FORGET_V1 supersédant l'événement. L'historique immuable n'est pas effacé ; la vue active exclut immédiatement le souvenir. Reçu canonique SQLite, state:forgotten. Une nouvelle opération sur un événement déjà oublié donne already_forgotten sans nouveau reçu ni événement. Paiement/biométrie/confirmation et demandes sont refusés avant tout effet.

Les autres textes sont présentés comme learnings importables, jamais exécutés ni promus automatiquement. Formats autres, export >1 Mio ou 50 conversations/5000 messages, >100 candidats sont refusés ; texte candidat <=2000 caractères.

POST `/v1/control/memory/import` {source,export,previewHash,selectedIds:[sha256],operationId} : l'app renvoie l'export et la sélection explicitement relue, 1..20 éléments uniques. Aucun stockage intermédiaire d'aperçu. Le propriétaire recalcule exactement l'aperçu ; hash ou sélection changés refusés avant écriture. Une transaction atomique unique insère les learnings sélectionnés et un checkpoint de reçu dans les tables events/memory_meta existantes. State:imported, importedCount, receipt {action:"memory.import",operationId,eventId,revision,at}. La date source est conservée si validée, sans inventer de date d'origine ; createdAt est la date de l'import. L'archive mensuelle existante est alimentée après commit ; SQLite reste la vérité si l'archivage échoue.
