# O9 — Runs voix : état terminal explicite

## Source réelle

Capture S24 en lecture seule du 11/10 (00:46) : `openclaw-plugin-mobile-ui/fixtures/s24-2026-10-11/o9-voice-unknown-runs.json`
(issue #110). Registre `~/.openclaw/clawmobile-companion/runs.json` (version 1, 17 runs) : 3 runs voix des 08/10 et
09/10 avec `transcriptState=interrupted` et `state=unknown`, sans `playback`, `clientRunId` ni `decision`. Aucun autre
stockage ne référence leurs identifiants.

## Cause

`terminal()` (`runs.ts`) tient un run voix pour terminal si `transcriptState` vaut `completed` ou `interrupted`, mais
`saveVoiceTurn` (propriétaire, appelé par POST `/sessions/{id}/voice-turns`) et `statusFromStoredRun` ne mettaient
`done` que sur `completed`, sinon `unknown`.

## Décision

- `completed` → `state: "done"`.
- `interrupted` → `state: "done"` avec `status: "interrupted"`. Une interruption (coupure de parole ou raccroché) est
  une fin normale du tour, pas une erreur : elle n'est pas `failed`. Le contrat des runs n'a que quatre états
  (`running`, `done`, `failed`, `unknown`) ; `status` porte la nuance, comme `expired` pour l'inactivité.
- `partial` reste non terminal (inchangé).

## Réconciliation

Dans les propriétaires existants, sans job ni migration :
- à la lecture du registre (`readCompanionRunRegistry`), un run voix au transcript final encore `unknown` est projeté
  terminal ; la prochaine écriture du registre le persiste ;
- `saveVoiceTurn` écrit directement l'état terminal ;
- un tour final reste final (garde `turn_already_final` inchangée).

## Tests (CI : étape « O9 voice runs terminal state… »)

- `scripts/test-voice-run-terminal-state.cjs` : registre amorcé avec les 3 runs capturés (mêmes clés, longueurs
  conservées, contenu neutre) ; aucun `unknown` après réconciliation, en lecture comme après écriture.
- `installer/termux-lite/test-companion-acceptance-voice.py` : la ligne de recette.

## Recette

`companion-acceptance.py` ajoute le contrôle `voice_runs_terminal_state` sur la lecture existante `GET /runs?limit=50`
(budget 4 s inchangé) : échec si un run voix au transcript final est `unknown`. Lecture seule.

Recette live (Claude, après `companion-deploy.sh`) : la recette automatique passe, et les trois runs capturés se lisent
`done`/`interrupted`. Aucune consultation opérateur.

## Retour arrière

Revert de la PR. Les runs gardent leur `transcriptState` ; aucune donnée perdue.
