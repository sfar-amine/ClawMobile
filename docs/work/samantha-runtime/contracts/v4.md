# V4 — rapport automatique des latences

L’analyseur A10 existant voice-m1-analyze.py ajoute à chaque exécution la section startup (schema samantha.voice.startup-latency.v1). Il rapproche strictement sid, src et turn=0 pour prewarm_app_ms, t00_to_t01_ms, t01_to_t07_ms et t00_to_t07c_ms. t00/t07c viennent de l’app ; t01/t07 du Companion. Les autres métriques A10 restent inchangées.

La dérive est comparée strictement à 1 ms quand la nouvelle représentation non tronquée est déclarée (`clock_drift_truncated:false`, producteur V2). Une égalité de 1000 µs reste admise, 1000.001 µs ou -1000.001 µs sont exclues. Pour les anciennes traces sans drapeau, le seuil A10 conservateur >=1000 µs demeure : une valeur égale à 1000 est exclue comme `unknown_truncated_boundary`, pas affirmée comme une dérive prouvée au-delà du seuil. Les deux listes et la politique sont explicites dans le rapport. Aucune précision ne se déduit du type float ou du sid. Les manques et inversions d’horloge restent comptés. p50 est calculé dès un échantillon ; p95 vaut null/p95_qualified=false sous 100 observations, jamais une promesse de percentile qualifié sur un petit groupe. `observed_p95_ms` fournit toutefois le percentile descriptif de l’échantillon disponible, explicitement non qualifié si `p95_qualified=false`.

Commande du harness existant : python3 scripts/voice-m1-analyze.py app.jsonl companion.jsonl --out latency-report.json. Aucun nouveau scheduler ; le rapport est généré automatiquement à la fin de la commande d’analyse de recette. Aucun KPI acoustique externe inventé.

Validation : 7 tests de rapprochement/statistiques/frontières explicites, plus corpus/analyseur 10/10. Base runtime af4132a ; ci.yml inchangé, aucune inclusion du code V2/V5 ou d’autre lot non fusionné. La couverture de recette des nouvelles sessions historiques dépend de V2 ; le rapport et ses fixtures sont indépendants en code. Aucun déploiement Codex.
