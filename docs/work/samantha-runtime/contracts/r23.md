# R23 / E1 — modification d'automatisation

**Route** : `PATCH /v1/automations/{id}`, garde owner (boucle locale, sans Origin, `x-clawmobile-owner-flow: v1`), budget 20 s
(CLI : `cron.list` ~3,6 s + `cron.update` ~3,5 s, relecture éventuelle ~3,3 s ; P0-1 réduit ces temps).
Capability `samantha.app.automation.edit` (planned, confirmation) dans la PR playbooks jumelle.

**Corps** : `{operationId, confirmationId?, name?, schedule?, message?, enabled?}` ; en-tête `If-Match: sha256:<base64url>`.

**Source de vérité confirmée sur le S24** (captures #131 et lecture seule du 11/10, `fixtures/s24-2026-10-11-r34/e1/`) :
`cron.list` porte `configRevision` pour chaque job ; `cron.update` accepte `{id, patch, expectedConfigRevision}`
(`CronUpdateParamsSchema`, patch fermé) et refuse une révision périmée avec `details.code = CRON_JOB_CHANGED`.
Formes de planification réelles : `every {everyMs, anchorMs?}`, `cron {expr, tz?, staggerMs?}`, `at {at}`.
Consigne : `payload {kind:"agentTurn", message}` (patch partiel accepté par `cronAgentTurnPayloadSchema`).

**Ordre** :
1. refus paiement du nom ou de la consigne (422 `automation_payment_excluded`), secrets (422), validation (400) :
   `every` 1 min à 30 j, `cron` numérique à 5 champs, `at` ISO UTC futur ; consigne de 4 000 caractères au plus ;
2. `If-Match` absent ou mal formé : 428 `automation_revision_required` ;
3. lecture owner (`cron.list`), 404 si absent ; automatisation protégée : 409 `automation_protected` ;
   consigne sur un payload non `agentTurn` : 422 ;
4. CAS préalable : révision différente → 409 `automation_revision_conflict` avec `currentRevision` ;
5. consigne ou planification d'un `agentTurn` sans `confirmationId` : 403 `needs_confirmation`
   `{scope:"automation.edit", reference:id, payloadHash:sha256(JSON canonique du patch validé)}` ;
6. opération native (reçu dans le registre des runs) : consommation de la confirmation, **un seul** `cron.update` avec
   `expectedConfigRevision`. `CRON_JOB_CHANGED` → `refused / automation_revision_conflict`. Réponse incertaine →
   **une** relecture : effet visible → `completed` ; révision inchangée → `refused / automation_update_not_applied` ;
   relecture impossible → `indeterminate` (503), jamais de rejeu. Même `operationId` → reçu stocké.

La planification `cron` garde le fuseau et le `staggerMs` du job ; rien n'est inventé.

**Choix de CAS** : la révision native par job, appliquée atomiquement par la Gateway, plutôt que la révision globale
R5-bis (#78), comparée côté Companion et donc sujette à une course. R5-bis reste l'invalidation de cache de la liste.

**Limite connue** : `protectedJob` teste `JSON.stringify(job)` ; la clé structurelle `payload` correspond à `\bpay`.
Sur le S24, les 18 automatisations sont protégées (14 seulement par cette clé). La règle du 10/10 est conservée :
aucun contournement ici, correction du prédicat chez son propriétaire, en PR séparée (avant/après, phrases positives
toujours refusées). Jusque-là, la route répond 409 pour toute automatisation réelle.

Retour arrière : revert de la PR ; la capability reste planned.
