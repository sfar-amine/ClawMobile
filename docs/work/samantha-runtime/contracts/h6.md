# H6 — garde fondée sur l’intention résolue

Décision d’Amine du 11/10 : aucun mot n’est bloqué par une garde paiement.
Pays, paysage, paiement, recharge, invoice, purchase, payload, un nom d’opérateur
ou un montant dans une description ne qualifient jamais une transaction.
La qualification vient exclusivement d’une décision v2 du fast path canonique,
obtenue avec checkOnly, autorité propriétaire et budget total de 1 seconde.
Aucun appel n’exécute la capability pendant cette qualification.

Le propriétaire automation résout seulement le message agentTurn ou le texte
systemEvent du job sélectionné. Nom, description et risk fourni par une requête
ne font pas autorité. Une résolution par détail ou action, jamais une par ligne
Control : en l’absence de qualification hôte vérifiée, la notification expose
une indisponibilité explicite et conserve la route détail/action existante.
Les gardes d’essai de skill et d’apprentissage utilisent la même décision.
Le détail skill reste une lecture de métadonnées ; enable/disable modifient la
configuration auprès du propriétaire existant sans exécuter d’instruction.
Ils conservent leurs gardes structurées ; seule l’intention réelle d’un essai
est passée au resolver, jamais un JSON inventé comme instruction.
Une intention transaction, destructive, sensitive ou external_send et toute
frontière humaine restent protégées. Une décision absente/invalide ou une
résolution incomplète interdit l’effet ; elle n’est pas présentée comme un
paiement identifié. Les politiques de confirmation structurelles demeurent.

Le propriétaire inactivity utilise la décision enregistrée, jamais le texte du
run. Les nouveaux runs Gateway conservent uniquement la décision issue de leur
fast path canonique ; les anciens runs sans décision restent conservativement
protégés. Les demandes paiement et confirmations humaines existantes restent
protégées indépendamment. Les noms et lignes des fichiers perdent la garde
lexicale financière ; masquage secrets, e-mails, PAN, OTP et chemins sensibles
conservent leur frontière de confidentialité.

Routes et capabilities inchangées : détail/action automation, skill et learning
utilisent leurs propriétaires existants. Aucun module du parcours paiement,
biométrie, OTP ou 3-D Secure n’est modifié. Aucun store, routeur ou retry ajouté.
R23 et E3 doivent fusionner cette correction pour leurs helpers partagés.

transaction sans mot financier, décision inconnue, contradictions de risques,
confirmation humaine, concurrence et absence d’effet avant garde. Les décisions
simulées sont synthétiques et ne valent pas une qualification S24. Les captures
Gateway S24 existantes fixent les formes des propriétaires ; Claude effectue
la recette opérationnelle. La suite CI locale entière doit être rejouée au SHA
final avant publication du reçu N/N et de « @claude prêt à fusionner ».
