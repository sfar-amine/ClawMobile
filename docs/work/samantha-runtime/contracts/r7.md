# R7 — versions et mises à jour en lecture

GET `/v1/updates` : `{success,state,receipt:null,items,current,lastKnownGood,available,updateAvailable,issues,actions:[]}`. Quatre entrées fixes : app, Companion, playbooks et termux-lite. La version Companion vient du package chargé, celle des playbooks du HEAD du snapshot figé `runtime-ui-playbooks/current` (marqueur `reporting/control_snapshot.py` obligatoire), celle de termux-lite du `source_commit` du manifeste courant vérifié par le propriétaire tier0-control.

La version Android appartient à l'app : faute de producteur canonique côté runtime elle reste `null`, avec `app_version_owned_by_android`. Une source absente reste `null` avec raison ; on ne substitue pas le workspace au snapshot utilisé. `state:partial` signale les informations manquantes.

La disponibilité concerne les releases déjà préparées dans le dossier existant du propriétaire, avec manifeste et fichiers vérifiés, date strictement postérieure au courant. Ce lot ne contacte aucun catalogue distant et ne promet aucune activation qualifiée. Date courante inconnue : `updateAvailable:null`. Une release altérée, `rolled_back_from` ou `last_bad` est exclue. Quand `soak_state` vaut `rolled_back`, `updateAvailable:null` et `updateReason:tier0_soak_rolled_back` signalent que le propriétaire doit qualifier la suite. Les releases vérifiées et plus récentes sont filtrées avant la limite de 100, triées par date décroissante. Aucun téléchargement, promotion, rollback, modification des liens current/LKG, du state.json ou de l'historique. Le helper `tier0-native-read.py` appelle seulement les lectures et la vérification du contrôleur existant.

Loopback uniquement ; Origin, Referer et Sec-Fetch-Site refusés. GET sans paramètre ; POST/PUT/DELETE 405, sous-route inconnue 404. Cache mémoire de 1 s, invalidé dès changement des liens current/LKG, du dossier releases, du state.json ou du pin playbooks ; les lectures concurrentes identiques partagent le même calcul. Les fichiers modifiés en place sont revérifiés après cette durée maximale. Aucun bytecode Python écrit dans le checkout. Lecture bornée à 3,5 s, erreur fixe `updates_unavailable`, sans secret ni chemin dans la réponse. Aucun operationId ni reçu d'action durable pour cette lecture.

Validation : fixtures de releases courante/ancienne/nouvelle, snapshot playbooks réellement épinglé, exclusion d'une release altérée, source absente, rollback, plus de 100 releases, cache et invalidation, frontières HTTP et invariance des fichiers owner. Tests tier0 existants et toutes les commandes CI runtime rejoués. Le test spécifique `scripts/test-updates-read.cjs` est exécuté séparément ; ci.yml reste inchangé pendant la PR R6 #27, conformément à la règle d'une seule PR modifiant la CI.
