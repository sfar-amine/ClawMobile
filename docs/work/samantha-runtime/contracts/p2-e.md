# P2-e — Diagnostic en lecture et export

GET /v1/control/diagnostic?contract=2 : enveloppe Control v2 et components {id,label,status,detail,checkedAt,version,endpoint}, logs {id,label,route}. Le verdict health/current.json existant est autoritaire et expire après 300 s ; aucun probe, réparation ou notification. Versions Companion depuis package.json chargé et OpenClaw depuis le package installé du préfixe canonique ; absence = null. Endpoint ADB fixe du verdict existant, jamais endpoint découvert. Termux/SSH et Tailscale restent unknown faute de preuve canonique dédiée ; Accessibility reste locale Android.

GET /v1/control/diagnostic/logs/{agent|installation|engineering}?offset=0&limit=20&revision=<sha256> : pagination de métadonnées, maximum 100 entrées/262144 octets/8192 lignes, sans suivi de symlink, aucune ligne brute ni message. Une révision différente invalide la continuation. Installation lit exclusivement l’historique s’il existe dans tier0/state.json ; pas d’historique inventé. L’agent utilise le journal du workspace par défaut ; workspace personnalisé sans journal = indisponible. Les formats non reconnus sont omis avec compteur filtered.

POST /v1/control/diagnostic/export {operationId} : owner natif local, sans Origin/Referer/Sec-Fetch-Site ; réponse {success,state,receipt,artifact}. artifact est une archive ZIP inline base64 (131072 octets maximum), nom fixe, MIME, taille et SHA-256. Android peut la partager ; aucune URL publique, archive serveur, conversation, audio, secret ou fichier credentials. Le registre existant des runs conserve le reçu et l’archive ; même operationId retourne le même résultat durable sans reconstruction. L’incertitude ne provoque aucun rejeu. La rétention reste celle du registre existant, pas de garantie infinie.

La projection est volontairement limitée aux métadonnées closes plutôt qu’à une redaction heuristique du contenu. Une disponibilité partielle ne constitue pas une qualification S24.
