# R14 — partage de fichiers entrants

Le stockage existant `companion-attachments` est conservé : aucun registre ou scheduler ajouté. Upload owner loopback, sans origine navigateur, en-tête `x-clawmobile-owner-flow: v1`. `x-clawmobile-attachment-id` est obligatoire pour l'upload binaire ; chaque fichier partagé fournit `id`. L'idempotence compare le hash du contenu stocké sous cet id et le MIME : même contenu réutilisé, contenu différent refusé. Aucun upload ne réserve d'opération dans le registre des runs et l'historique reste inchangé. La réponse conserve les champs historiques et ajoute `{success,state,receipt}` ; le reçu est déterministe par contenu/id/MIME. `x-clawmobile-operation-id` n'est plus nécessaire.

`POST /v1/attachments` reçoit le corps binaire. `POST /v1/attachments/share` reçoit `{files:[{id,mimeType,base64}]}`. Maximum 5 fichiers, 10 Mio par fichier et 25 Mio par partage ; dossier limité à 500 Mio. Formats fermés JPEG, PNG, WEBP, GIF, PDF et texte UTF-8 sans contrôles ; validation des signatures, rejet de contenu HTML/SVG/XML déguisé en texte. Aucun shell ni exécution.

Les identifiants sont stricts, les collisions refusées, fichiers 0600, ouverture exclusive et lecture sans suivi de liens. Téléchargement `nosniff`, disposition attachment pour les non-images. Les erreurs publiques sont fixes, aucun nom ou contenu journalisé.

Purge paresseuse au démarrage et à l'upload, après 30 jours ; aucun fichier encore attaché à un run n'est évincé. La suppression R3 conserve la liste de nettoyage dans son reçu existant, puis enlève uniquement les fichiers non référencés par un autre run. Une reprise de suppression termine un éventuel nettoyage interrompu. Les fichiers de runs protégés ne sont jamais supprimés par cette action.

Intégration Android et recette S24 restent à Claude. Le propriétaire de paiement et ses fichiers ne sont pas modifiés.

Les fichiers rattachés à un run restent conservés au-delà des 30 jours, jusqu'à la suppression du dernier run qui les référence. Si cette protection empêche un upload sous le quota, réponse `refused / quota_full` sans éviction. Les anciens `.img` ne sont plus servis : 404 ; aucun renommage implicite. `POST /v1/runs` avec une pièce inexistante renvoie 404 `attachment_not_found` avant création d'un run. Les tests couvrent l'historique inchangé, le rejeu, les images HTTP, et appendAttachmentContext pour fichiers et images.
