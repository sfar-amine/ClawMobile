# O1 — preuve du garde réseau des consultations Orange

L’entrée canonique reste le registre → Capability Graph → `telecom.maxit_guarded_service`. Le wrapper consultation utilise la nouvelle commande interne `with-consultation-receipt` du propriétaire existant `android-network-mutation-guard.py`. La commande générique `with-wifi-off`, notamment utilisée par le paiement, reste inchangée à l’octet près (test AST sur capture réelle).

## Autorité et reçu

`SAMANTHA_MAXIT_LEASE_ID` n’est qu’un pointeur 32 hex. `verify-consultation-lease` lit le bail existant sans lien symbolique, vérifie type/purpose/âge, identité de naissance, processus propriétaire vivant et sa commande réelle `/proc` (fichier garde canonique et commande consultation fixe), puis la vraie chaîne d’ancêtres du demandeur. Un Python ordinaire créant son propre bail reste refusé. Le FD du lock observé n’est pas une attestation autonome du détenteur noyau : il confirme la cohérence du process canonique, dont le code verrouille avant de créer le bail et garde ce lock jusqu’à la fin. Le wrapper refuse avant DNS/service sans cette preuve. Aucun second lecteur/store ou daemon. Le `mutation_lock` existant sérialise les consultations avant leur snapshot ; acquisition bornée 5 s, refus `guard_busy` sans traceback ni effet si occupé.

Le garde produit après restauration `network_guard: {wifi_initial, wifi_disabled, dns_ready_ms, restored, lease_id, path}`. Les trois booléens et le bail viennent du propriétaire ; DNS est l’attente bornée du wrapper (0–8000 ms ou null si indisponible). `path` vaut `wifi_off`, ou `cellular_bind_wifi_on` avec `reason: http_400_wifi`. Une restauration en échec interdit le succès, conserve le bail pour le reconciler existant et renvoie `restoration_failed`. L’enfant tourne dans un groupe de processus isolé. Ses deux flux sont collectés avec une limite combinée stricte de 1 Mio pendant la lecture, jamais après une collecte illimitée. Le garde arrête le groupe avant restauration (TERM 0,5 s puis KILL 1 s, observation des membres vivants). Les descendants qui conservent ou ferment les flux ne continuent pas après le retour. Sans preuve de cleanup, la restauration reste au mieux une tentative : `restored:false`, bail conservé, reçu dégradé. Un signal ou une erreur pendant cleanup ne produit jamais un faux succès. Le scan de groupes est borné à 65 536 PID ; ambiguïté ou dépassement interdit la certification, sans état healthy.

Le repli reste interne. Après l’échec HTTP 400 seulement (appel O2), `prepare-consultation-cellular` vérifie le même bail, exige Wi-Fi initial actif, restaure ce Wi-Fi via le propriétaire et le relit, puis inscrit le chemin dans ce même bail. Aucun Wi-Fi n’est réactivé si l’état initial était inactif. Le garde final lit cette attestation propriétaire ; un JSON enfant affirmant le repli ne suffit jamais. O2 branche cet appel sur son transport validé, sans mutation UI parallèle.

La projection Orange retrieval conserve seulement les deux champs de transport fermés ; le Capability Graph porte le `network_path` validé dans son résultat A8, sans remplacer planned_route/actual_route. Le validateur pur `telecom.network_receipt.valid_network_guard(value, require_restored=True)` est réutilisable par O3, sans catalogue parallèle.
