# V5 — voix par session, réglage conservé dans Android

Base runtime `af4132a`. Le contrat du fichier 23 remplace les anciennes routes et le stockage runtime du fichier 18 : aucune route PUT `/v1/voice/voice`, aucun fichier de préférences Companion. Claude conserve `VoiceSettings.voiceId` dans les préférences Android et transmet `voice` à l’ouverture.

GET `/v1/voice/voices`, natif loopback sans Origin/Referer/Sec-Fetch-Site, retourne `{schemaVersion:1,model:"gemini-3.8-live",appliesTo:"next_session",items:[{id,label,current,validated,...}]}`. `current:null` signifie que le runtime ne connaît pas le choix Android. « Par défaut » a `id:null`, `validated:true`, `validation:"existing_default"` : il réutilise strictement le setup déjà présent. Les huit candidats Puck, Charon, Kore, Fenrir, Aoede, Leda, Orus et Zephyr sont tous `validated:false`, sans qualité vocale supposée. Les flags sont des déclarations du catalogue source, modifiables après qualification revue ; aucun registre ou mécanisme de validation runtime.

POST `/v1/extensions/claw-live/token` et POST `/v1/extensions/claw-live/prewarm` acceptent un champ `voice`, strictement une chaîne du catalogue, null ou absent. L’amorçage natif WebSocket existant `/v1/extensions/claw-live/socket` accepte le même nom via son paramètre `voice`. Valeur inconnue, casse incorrecte, chaîne vide, tableau, objet ou booléen : HTTP 400 `unknown_voice`, avant création d’un token ou connexion fournisseur. Aucun coercition. Les routes token/browser gardent leurs bornes déjà existantes ; la liste est uniquement native.

Absent/null : setup actuel exact, sans speechConfig. Nom explicite : seule addition au setup, `generationConfig.speechConfig.voiceConfig.prebuiltVoiceConfig.voiceName`. Modèle `gemini-3.8-live`, modalités AUDIO, transcriptions, outils, routes audio et duplex …DZI1 inchangés. Un choix est figé sur sa connexion/session ; un prewarm de cycle de vie ne remplace pas la voix du propriétaire actif. La session suivante peut adopter un autre nom et crée son setup, y compris dans le même fil après detach protocole 1 laissant le fournisseur chaud ; reconnexion/résumption conserve la voix de la connexion concernée. Pas de modification d’une session ouverte, ni de stockage, ni de journal contenant token ou secret.

L’acceptation technique d’un candidat permet la qualification de Claude, sans constituer une validation fournisseur. Avant activation de la sélection Android, Claude ouvre chaque candidat jusqu’à `setupComplete`, sans envoyer d’audio ; les refusés sont retirés du catalogue et les acceptés sont marqués après relecture. Claude/Amine vérifient ensuite l’écoute et trois sessions par choix : différence de médiane de démarrage sous 50 ms. Codex ne déploie ni ne qualifie le S24.

Preuves locales : `scripts/test-voice-choices.cjs` couvre la liste, ses bornes HTTP, toutes les valeurs admises/refusées avant mint, absence/null comparés au setup historique, captures de setup par fournisseur simulé, amorçages HTTP et WebSocket natifs, connexion active inchangée, choix à la session suivante et aucune écriture dans le home de test. Les tests warm/detach/cancellation et la CI courante sont rejoués localement. Le nouveau test est exécuté séparément ; ci.yml reste inchangé pendant la PR qui en est propriétaire.
