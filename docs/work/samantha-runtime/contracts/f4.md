# F4 — Notifications structurées `{title, body, fields[]}` côté Companion

Source confirmée sur le S24 (issue #97, capture `fixtures/s24-2026-10-11b/f4/runs.summary.notifications.json`) : l'écran Notifications lit `GET /v1/runs?limit=40&summary=1` (`runs.ts`, `~/.openclaw/clawmobile-companion/runs.json`) et affiche `run.result`. Sur 17 runs : 3 Markdown en ligne (`**…**`), 6 JSON brut d'opération, 6 textes simples, 2 vides (voix). Lecture réelle : 80 ms.

## Projection
`listRunSummaries` (chemin `summary=1` seulement) ajoute à chaque run `notification` (`notificationText.ts`, fonction pure, aucun store ni appel Gateway) ; **`result` reste inchangé** et sert de repli.

```
{version:1, format:"json"|"markdown"|"key_value"|"plain", title, body, fields:[{key,label,value}], emphasis?:[{start,end}], rawFallback:"result"}
```
- **JSON objet** (≤ 16 Kio) : `title` = demande (`userText`) sinon « Action terminée / en échec » ; `fields` = scalaires lisibles (booléens « oui/non », libellés français connus), objets imbriqués jusqu'à 2 niveaux, lignes `{title, value, unit}` en un champ chacune ; clés techniques retirées (`ok`, `run_id`, `source`, `transport`, `ui_used`, `latency_ms`, `observed_at`, `blocked_by`…) ; 12 champs et 120 caractères par valeur au plus.
- **Markdown** : `body` = texte sans `**`, sans perte de caractère ; `emphasis` = plages en gras dans `body` (rendu natif, sans WebView).
- **`clé: valeur` / `clé=valeur`** sur au moins 2 lignes : `fields`.
- **Sinon** : `plain`, `body` = texte brut. Résultat vide : `notification:null`.

## Budget
Route existante `/v1/runs` (ligne de recette déjà présente) ; projection < 2 ms pour 100 résultats de 1 292 caractères ; test de lecture complet en quelques ms, sans Gateway.

## Tests
`scripts/test-notification-structured.cjs` (CI) : les 17 runs réels (3/6/6/2), texte brut identique, aucun `**` ni JSON dans la projection, gras exacts, champs batterie et cartes, formes `clé: valeur`, repli JSON invalide/tableau/> 16 Kio.
