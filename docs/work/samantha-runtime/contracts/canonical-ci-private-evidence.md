# Canonical CI: private in-process evidence API

The single CI owner remains `tools/localci.py`. Its existing CLI and all workflow steps are unchanged. `run_ci_evidence(repo, sha, pr, output, subject_path=..., expected_subject_digest=...)` is an explicit Python API of that same owner, invoked only by a trusted host. Importing the module, parsing an artifact, or checking delivery status never starts CI.

The import-time source digest is frozen separately from disk/HEAD; a later committed source change cannot relabel already loaded Python. Before execution it checks a full SHA40, the GitHub PR/head/base, an exact committed regular JSON subject and its expected canonical digest, and the actual runner file against the runner commit. The output log must be fresh. It invokes the SAME canonical CLI once under a Bubblewrap PID namespace; that CLI calls the existing `run_ci`. A private capability is issued only after the actual owner process returns exit 0 and its namespace teardown stops detached descendants. Namespace/Bubblewrap absence produces no private capability / NOT_IMPLEMENTED, never a bare fallback. Host mounts, environment and network are preserved, except private `/proc` and `/dev` needed for this lifetime boundary; this is not a confidentiality/network sandbox. GitHub head/base/PR and runner bytes are rechecked after completion. The proof identifies repository, head/base/PR, runner commit/digest, workflow bytes, committed subject and durable log digests. A source artifact's presence under the tested head proves identity, not that its semantic contents or assertions were executed.

`verify_ci_evidence` accepts only that producer's opaque instance in the same process/module. It rechecks GitHub identity and current log/runner digests, then supplies G1 evidence to the existing DeliveryQueue host callback. It does not rerun CI, poll, or accept a claimed PASS from JSON, a note, a log marker or deserialization. A false success marker printed by a failing workflow step remains a failure. Pickling the proof is refused. After process restart the private instance is gone: verification is NOT_IMPLEMENTED; the saved public metadata cannot recreate admission and CI is not automatically regenerated.

This is not a cryptographic signature, a new durable authority or protection from hostile Python in the trusted producer process. The current CI executes steps under the host user and is not an OS sandbox against malicious same-UID code. No key, signing service, registry, store, new runner, daemon or production/model access is introduced. The explicit API retains the normal CI network/environment semantics; only fixture tests ran during implementation. A durable cross-process private authority is not implemented.

Scope is runtime/playbooks/context workflows already owned by this runner; the new subject API does not add another Android path. G4 LIVE, G5 latency/admission budgets, final multi-repository combination, activation and loaded identity remain separate and cannot be inferred from this proof. The playbooks adapter intentionally leaves G4/G5 unavailable, so G1 alone cannot permit publication.

Tests are in the already registered `tools/test_localci.py` workflow command. They run short disposable workflows with fake GitHub metadata, not another full Samantha CI. Canonical exact-head PR CI of this change still runs later through the normal delivery queue; these fixtures do not replace it.
